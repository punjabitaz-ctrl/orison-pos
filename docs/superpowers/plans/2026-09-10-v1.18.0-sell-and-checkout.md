# v1.18.0 Sell & Checkout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make the running total impossible to lose sight of on a phone, and give the catalog and the charge screen the same calm surface the shell got in v1.17.0.

**Architecture:** The three repeated pieces of catalog markup — the category chip, the product tile, the cart bar — move into `components.js` as pure string builders beside the launcher tile, and `catColor()` stops being copy-pasted in two screens. `register.js` keeps all behaviour (scan, serial capture, discounts, stock mirroring) and changes only what it renders and when.

**Tech Stack:** Vanilla ES modules, no build step. `node:test` for the pure pieces, browser verification for the rest.

## Global Constraints

Same as v1.17.0 — see `docs/superpowers/plans/2026-09-10-v1.17.0-shell-and-navigation.md`. In short: no build step, no third-party script, everything user-supplied through `esc()`, money through `fmt()`, targets ≥44px, release protocol mandatory, and all four gates green before any commit.

**Baseline:** v1.17.0 — backend-sim 446, client units 269, pdf-smoke 19.

**Backend is not touched by this release.**

## Departure from the spec, to be recorded in the release notes

The spec says an out-of-stock tile is "dimmed and non-tappable". It ships **dimmed but still tappable**, because tapping it raises a toast naming the item and why it cannot be sold. A dead control teaches nothing, and this design's whole premise is that nothing should have to be learned.

### Task 3: The pinned cart bar

**Files:** `public/index.html`, `public/js/screens/register.js`

The substantive change. Today `renderCart()` calls `openSheet()` on **every add**, so a full sheet covers the catalog each time an item goes in, and the running total is invisible the moment it is dismissed.

- [ ] Add `<div id="cartbar" class="cartbar hidden"></div>` immediately before `#tabbar` in `index.html`.
- [ ] `renderCart()` splits by viewport: desktop fills `#regCartPanel` as now; phone and tablet fill `#cartbar` and only re-render the sheet **if the sheet is already open**.
- [ ] Tapping the bar's body opens the full cart sheet; the bar's Charge button routes straight to checkout.
- [ ] The bar hides when the cart is empty, and on screen teardown.
- [ ] `node --check`; commit.
